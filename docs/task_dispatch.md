# 当前园区任务调度第一版

> 阶段开发历史：以下“当前”“最新”均指对应章节当时的阶段，不能作为 2026-10-20 的运行说明。当前模块流程见 [CURRENT_RUNTIME.md](CURRENT_RUNTIME.md)，当前验证见 [VALIDATION_20261020.md](VALIDATION_20261020.md)。

任务层现已从指定车辆的固定运输脚本中分离，入口为 `TaskDispatcher`。提交 `TransportWork(task_id, loading_node, unloading_node, release_time, priority)` 后，由动态车队注册表提供可接单车辆，选择静态路线 ETA 加泊位服务排队估计最小的车辆；同分按车辆编号稳定选择。任务先按优先级、释放时间及任务编号处理。这是贪心基线，尚未预测动态堵塞或优化多个车辆的联合任务分配。

任务流程：派单 → 前往装货位或候选等待位 → 停稳装货 → 前往卸货位或等待位 → 停稳卸货 → 完成 → 自动接下一单。装卸各默认 5 秒，以执行器提供的单调调度时钟计时。优先级不改变已经执行的任务；等待晋升按加入队列的时间排序。

## 占用与执行约束

- 泊位/等待位在下发驶入命令时就预约，当前停车点继续占用；只收到实际车尾清空事件后才能释放原位置。服务完成、生成路线、估计到达均不代表物理离开。
- W5/W6 等共享入口用服务节点的 `occupation_resources` 联合互斥，正在驶入的车辆也计入。路由禁止使用其他车辆已占用或已预约的节点和通道。
- 泊位忙时，只使用拓扑确认可在目的地占用期间等待、进出连接无需待验收且能继续到目的地的等待位。没有合适等待位则保留原位置，不凭空建立道路停车点。
- 闲车占住后续任务需要的装卸位、入口或中间访问通道时，安排真实移车命令；车尾清空前仍保留原占用。与后续任务无关的已完成车辆不自动移动。
- 到达必须同时匹配命令编号、车辆访问编号、原泊位释放事件和停稳观察。旧车申请离园后停止接新单，完成当前任务后交由出口后端处理。
- `resource_snapshot` 只返回任务层泊位资源。确认离园前必须与道路、路口、等待及出口管理器资源合并，不能用此快照冒充全部资源清空。

路口与道路仍由现有 `TransportController`、FIFO/共享区域预约和容量检查执行。用户提供的冲突区时间窗、滚动优化、出口未来容量与公平性搜索尚未替换这套基线。

## 验证入口与范围

```bash
.venv/bin/python scripts/validate_task_dispatch.py
/usr/bin/python3 scripts/validate_ue_task_dispatch.py
.venv/bin/python scripts/check.py
```

轻量入口使用当前六仓库的真实服务路网，按离散事件推进：路线 ETA 后生成到达事件，**不模拟车辆动力学或碰撞**。覆盖 4 车/12 个跨仓任务、3 车/4 个同泊位排队任务，以及运行中逻辑新车加入、旧车排空任务后离场。证据为 `runs/task_dispatch/acceptance.json`。

UE 入口执行两条同时运输任务：`Car_0_0: W1-loading → W3-unloading`、`Car_0_1: W2-loading → W4-unloading`。初始夹具将两车放到装货位，停留 5 秒后由调度器发出运输命令；行驶期间只使用实际油门/转向，按测得整车包络离开初始泊位确认车尾释放，实际到达停稳后卸货计时。闲车临时隐藏并关闭碰撞，完成车保留在卸货位直到测试结束；结束恢复 24 车与 API，不控制相机、不修改保存地图。世界时间流速使用 4 倍，装卸 5 秒是调度时钟的真实 5 秒。

`ValidatedServiceRoutes` 将调度器选出的准确服务边序列绑定到已有测试轨迹，核对几何、方向、速度和容量别名；该首版仅绑定装卸节点间的既有轨迹；新的连续入口使用下述通用拼接器。等待节点、绕行或不同入口路线未绑定时明确拒绝 UE 执行，不悄悄换成另一条路线。首版 UE 测试覆盖两车运输与实际服务事件，不代表六仓库任意任务、连续排队及动态门口已投入 UE 运行；新增 W3/W4 卸货位的货厢落地视觉效果也不据此宣称通过。

## 连续执行与实际等待（最新验收）

`ServiceRouteGeometry` 按派单器选择的确切有向边拼接标准道路及等待位动作，校验源几何与交通许可；`ContinuousTaskExecutor` 持续观察所有参与车辆，根据实测车尾清空和停稳到达推进任务，保留停车车辆占用，继承未释放的道路预约再续接下一段。移动中或缺少车辆观察时拒绝续接。其 `resource_snapshot` 汇总任务泊位、道路占用/承诺、共享区域与路口资源；门口后端仍需更新生命周期观察并确认实际出园。

UE 双车 **3/3 任务、5/5 段移动通过**，耗时 178.0 秒，最大偏差 0.432 m。Q4 实际停稳等待约 43 秒，W3 前车车尾清空后才晋升，前车自动接下一单；零车身障碍接触、零车辆碰撞。全部参与车辆持续保留，任务间不传送或隐藏。结束恢复 24 车、API、时间流速和物理参数，地图未改、相机自由。完整检查 **201 项测试及 Phase 0～4 通过**，日志 `runs/continuous_tasks/project_check.log`。

当前运行配置排除候选进出边。Q3 标准出口暂缺通向本组 W3 目标的合法换道连接，因此选 Q4；不恢复发生碰撞的候选倒车出口。该结果仅覆盖代表性连续运输与真实排队，不宣称任意六仓库任务、所有等待路径、真实门口及 W3/W4 货厢落地视觉效果全部完成。证据、复现入口和范围见连续任务验收（原文档 `ue_continuous_tasks_acceptance.md` 未随本仓库提供）。
