# 架构约定（Phase 0～4）

## 数据与坐标

- 所有长度为米、时间为秒、速度为 m/s，角度为弧度；世界坐标右手系，正 heading 从 x 轴逆时针旋转。
- `VehicleState` 同时存储世界状态与道路状态；`s` 从有向 Edge 起点沿中心线累计，横向误差向道路左侧为正，航向误差为车头方向减道路切向。
- 归一化 heading 位于 `[-pi, pi)`。
- 车辆尺寸采用 0.12 m × 0.08 m，独立于地图宽度；Safety Envelope 在 OBB 每条边外增加配置 margin。
- 公共 Task、Reservation、RoadState、Movement、ConflictZone 已有数据模型；Task 执行器已接入，Reservation 执行器仍属于后续阶段。
- RoadEdge 存放静态地图信息，RoadState 存放运行时容量/占用信息，避免核心地图被运行统计污染。

## 地图与路径

`RoadGraph` 验证唯一 ID、节点存在性、中心线端点与节点一致，以及 Movement 的入/出边连接关系。每个道路方向使用独立 Edge，连通不自动代表转向合法；合法转向必须由 Movement 显式声明。最终园区布局暂未固定。

几何层处理分段线性 centerline、投影、插值、沿线距离及切向。通用 `match_pose` 利用距离与航向区分相向道路；已知路线的运行链路仅在当前与下一条 Edge 之间转换，防止临近道路误匹配。后续复杂路口将补充独立 Movement 路径匹配与定位不确定性处理。

最小场景在 8 条有向 Edge 组成的圆角闭环中运行；弧线离散为折线，车辆通过合法 Movement 接续直路和弯道。最小场景不包含多方向交叉冲突。

## 控制与时间

```text
仿真 VehicleState
  → Route-aware Map Matching
  → Pure Pursuit + 横向/航向反馈
  → 道路限速 + 弯道限速 + 基础跟车速度上限
  → ControlCommand(v_target, omega_target)
  → 差速运动学
  → 新 VehicleState
```

运动学采用 50 Hz，跟踪与记录采用 20 Hz。20 Hz 不是 50 Hz 的整数分频，故采用仿真时间 deadline 定时器，触发误差小于一个基础步长，不以 `sleep()` 或墙钟控制系统。控制时刻间距交替 0.04/0.06 s。

运动学限制速度、角速度和加减速，按步内平均线速度和恒定角速度积分。第一轮只支持前进。控制包具备序号、时间戳与 TTL；过期指令进入制动而不继续执行旧目标。序号检查接口已定义，网络收包乱序过滤将在通信阶段接入。

Pure Pursuit 使用 `L_d = L_0 + k_v*v`，按路径跨 Edge 获取目标点，再叠加负横向/航向反馈。控制器在道路边界前提前应用下一条道路的限速。基础跟车沿同一 Edge 的 `s` 排序，以净间距、时间车头距与停车距离限制后车目标速度。跨道路队列与下游容量控制属于 Phase 4。

## 验收

每步对车辆 OBB 进行 SAT 检测，接触也记为不安全；Safety Envelope 单独检测。当前指标采用违规 pair-step/vehicle-step 次数，不冒充独立事件数量。任何碰撞、包络重叠、同道路 FIFO 交换、限速/运动约束违规均导致验收 FAIL。

通过还要求每辆车累计行驶至少一个环路长度，且最大横向误差不超过 0.06 m。路径进度从起始道路位置扣除，避免靠高起始位置获得虚假的圈数。异常初始 spawn 直接拒绝。

所有随机扰动尚未接入，当前属于规划 Stage 1 Ideal 的基础部分。后续 Safety Supervisor 要处理 stale、timeout、预约有效性等输入，当前基础约束不代替完整安全层。


## Phase 3：静态路由

`routing.shortest_path` 以 `(node_id, incoming_edge)` 为搜索状态，边权为 `length / speed_limit`。节点级搜索会误删“到达同一节点更慢，但允许后续转向”的合法路线，因此进入道路必须属于搜索状态。Dijkstra 使用零启发式，A* 使用直线距离除地图最高限速的可采纳启发式。所有后续转向必须经过显式 Movement，路径返回 Edge ID 序列。离线泊位重新出发时没有进入道路约束，运行中有进入道路约束的调用可传 `incoming_edge`。

不可达目标抛出 `NoRouteError`，未知节点/算法等配置问题抛出 `ValueError`；同起终点的纯路由查询返回零代价空路线。运输任务要求起终点不同，无需运输的任务会明确记为 FAILED。搜索按道路 ID 排序，保证固定输入的结果可复现。

## Phase 3：任务与服务

```text
Task(PENDING)
  → release_time 到达 + 车辆空闲 + 目的站泊位可预留
  → 静态路由 + EN_ROUTE
  → Pure Pursuit 非循环路径 + 终点减速
  → 世界坐标到达阈值内 + 车辆已停止
  → ARRIVED（必要时排队）
  → SERVICING
  → 固定服务时长满足
  → TASK_COMPLETE
  → 下一条指定车辆任务
```

Task Manager 与车辆运动解耦，接受仿真时间和到达/驶离事件。每车按提交顺序执行任务，跨车辆按释放时间、优先级、任务 ID 排序；后提交的高优先级任务不打乱同车 itinerary。随机任务使用局部 seeded RNG 生成指定车辆往返任务，循环任务按指定停靠顺序重复运行。

任务中的目的地可以是逻辑站点（W/S）或普通节点；站点解析到独立离线泊位节点（w0/w1/w2 等）。每站总泊位数等于服务容量加等待容量，必须在出发前预留，包括即将到达的 committed 车辆。容量满时保持 PENDING 并留在起点。若某个空泊位不可达，继续尝试该站其他空泊位；所有可用泊位不可达时任务 FAILED，不遗留容量承诺。

服务容量是逻辑装卸资源，按到达时间 FIFO 获取；本阶段车辆在自己的泊位等待和服务，不搬运到独立装卸台。任务完成只释放装卸资源，车辆仍占用实际泊位；下一任务出发并驶离安全距离后才释放泊位。这样后续车辆不会驶向尚未离开的已完成车辆。原地朝向调整通过差速运动学执行，路线切换不修改 x/y/heading。

运输场景保留全部车辆的世界状态，停放、等待和服务中的车辆也参与每步碰撞审计。道路执行通道限制为一辆正在运动的车辆，让本阶段验证任务生命周期而无需提前实现路口调度；Phase 4 将替换这项限制。控制 20 Hz、任务更新 5 Hz、运动学 50 Hz，全部使用仿真时间。

每个 TaskRecord 保存路由、实际目标泊位、释放/出发/到达/服务开始/完成时间和失败原因；`events.jsonl` 保存所有状态转换。验收要求全部任务完成、横向误差在阈值内、无碰撞/包络重叠/容量及运动约束违规。固定场景还必须实际触发满载和拒绝准入。


## Phase 4：并行道路与局部 FCFS

Phase 3 串行仿真保留作回归检查，`FCFSTrafficSimulator` 复用任务、服务、运动学、Pure Pursuit、日志和安全审计，扩展为并行车辆执行。出发进入第一条道路也必须经过容量与入口净空检查，实际 x/y/heading 始终由运动学更新。

临时地图将每次穿越路口表示为显式连接 Edge：

```text
incoming road → controlled connector → outgoing road
```

连接 Edge 的中心线覆盖直行或转弯，独立路口配置声明其控制范围及下游 Edge。合法转向仍由 RoadGraph 的 Movement 验证。这里的连接 Edge 是运动路径，不是 Phase 5 的时间窗 Reservation。

车辆距当前道路末端 ≤ 0.35 m 时提交入口请求。同一道路先选前车，再按首个请求的仿真时间、车辆 ID 排序；重复请求更新位置，保留首次请求时间。已授予的同一路口只有一个持有人，不同路口可以同时放行。严格 FCFS 不绕过容量不足的队首请求，作为后续优化的保守基线。

授予前同时检查出口处前车净空，以及 `current + committed < storage_capacity`。授予时就预留出路容量，车辆进入出路后把 commitment 原子地转为 current，避免重复计数。物理道路位置按车辆中心计数；路口通行权则必须等完整车体和保守安全边界离开控制区域才释放，不能仅凭中心线进入下一条道路就放行下一辆。

未获准车辆按停车距离、控制反应间隔与净余距离平滑减速，停在道路终点之前 0.12 m 的控制线。跟车也沿路线累计弧长，覆盖前车已进入下一条道路的情况。同一道路队列持续审计，禁止越过前车。配置中的车身尺寸和安全边界决定停止偏移的最低要求。

每个运动学步骤审计全部车体 OBB、Safety Envelope、非法路口占用、停止线、current/committed 道路容量、服务容量、FIFO、限速和加减速。任何违规或未完成任务均导致 FAIL。并行验收使用线速度大于停止阈值的车辆数，不把原地旋转当成同时行驶。

初始车辆位于道路分界节点时，默认采用出边坐标；特殊满载夹具通过 `initial_edges` 指定停放车辆所占道路，避免容量归属歧义。夹具道路容量不超过 `floor(length / (vehicle_length + standstill_gap))`，路口连接道路额外限制为单车。

`traffic_events.jsonl` 保存请求、授权、实际入场和车尾清场事件。平均/最大路口等待时间从首次入口请求算到授予；吞吐量按完成任务数除实际仿真时长计算，包含运输及服务时间。它们只描述对应测试场景，不代表最终园区性能。离线回放使用真实记录位置和路口持有人，不调用调度器生成新轨迹。
